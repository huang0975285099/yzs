# 2026-11-16

## 云值守：同步停滞 + 统计接口超时修复

### 根因
- 待处理订单同步在单个分页失败时整轮中止（生产 synced_at 停在 16:35，外部仍有 141 单待处理）。
- 统计接口全表扫描 `trade_abnormals`：/stats 16.4s、/stats/operators 13.8s、/stats/inspectors 20.3s、/stats/daily 16.2s、/me/daily-stats 11.3s，均超过前端 15s 超时。统计页同时触发 3 个重查询，把数据库拖慢，连带记录接口也超时。

### 改动
- `backend/scheduler/sync.go`：待处理每 2 分钟、已处理每 30 分钟；独立 Redis 锁；共享 HTTP 客户端 + 分页重试（3 次）+ 连续失败熔断 + 8 分钟 deadline；内部已处理订单不再逐条刷新 synced_at；记录 last_sync。
- `backend/handlers/trade_detail.go`：空池返回 200 + `data:null` + meta，并在长时间未同步时异步补同步（2 分钟限频）。
- `backend/handlers/trade_handle.go`：/stats 增加 30s Redis 缓存；排行改为按 handled_by_id 走覆盖索引，姓名从 users 补。
- `backend/handlers/stats.go`：/stats/operators、/stats/daily 改读 daily_stats 日表；/stats/inspectors 只聚合当日复查。
- `backend/handlers/user.go`：/me/daily-stats 全量改读 daily_stats。
- 前端：空池响应兼容（OperationsPage/MyHandledPage）；stats 接口超时 30–45s；超时与其他错误提示区分。

### 实测
- 排行 16.4s → 1.7s；操作员统计 13.8s → 0.24s；质检员统计 20.3s → 0.24s；日统计 16.2s → 0.19s；个人日统计 11.3s → 毫秒级。
